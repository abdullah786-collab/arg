Requirements

  • WordPress 6.0 or newer.
  • PHP 8.2 or newer. On older PHP versions the plugin shows a notice and does not load.
  • Ad code from your advertiser or ad network, or your own HTML.

Installation and activation

  1. In WordPress, open Plugins → Add New → Upload Plugin.
  2. Choose the plugin ZIP (revguard-pro-1.0.0.zip) and click Install Now. If your download is a larger package, unzip it first and upload only the plugin ZIP inside it.
  3. Click Activate. A RevGuard Pro menu appears in the admin sidebar.

Activation creates the plugin's database tables and gives the Administrator role access to the plugin (see Who can use it). The plugin works on its own and does not need a licence key or a service of its own. See Privacy and external requests for what your ad code may load in your visitors' browsers.

You can also install it by uploading the unzipped revguard-pro folder to wp-content/plugins/ and activating it from the Plugins screen.

How it works

You create Ads, optionally collect them in Groups that rotate, and decide where they appear with Placements — or place them by hand with a shortcode or block. Everything is decided on your server when a page is built. RevGuard Pro adds no JavaScript of its own to your visitors' pages; see Privacy and external requests for what your ad code may load.

If another plugin also inserts ads automatically, the same ad can appear twice. Use one automatic inserter at a time: either turn off Insert ads automatically in Settings, or deactivate the other plugin. Shortcodes and blocks work either way.

Dashboard

The Dashboard gives you an at-a-glance view:

  • At a glance — real counts of your ads and placements, and (if you may view analytics) recent impressions.
  • Suggestions — advice about how your ads are set up. These are suggestions only. They are not an approval, a certification or a compliance check, and they never block you from saving anything.

If one panel cannot be loaded, it shows a short message and the rest of the page still works.

Ads

An ad is the content you want to show. Open RevGuard Pro → Ads to see them in a standard WordPress list with status filters, bulk actions (activate, deactivate, delete) and row actions.

Add or edit an ad

FieldWhat it does

Ad codeThe HTML you want to show. It is displayed in the form as plain text and is never run inside the admin. See What ad code accepts.

The form also shows, read-only, who the ad is shown to (Everyone or Restricted by rules) — see Targeting.

What ad code accepts

Ad code is HTML. How it is treated depends on who saves it and on one setting:

  • Filtered (the default). The code is passed through an allowlist when it is saved and again when it is shown. Kept: text formatting, headings, lists, links (http, https, mailto only), images and pictures, div, span, ins, and the attributes class, id, data-*, style (WordPress's safe CSS only), href, src, srcset, alt and a few layout attributes. Removed: script and frame tags, forms, event handlers such as onclick, and javascript: links. As with WordPress's own filter, the text that was inside a removed script tag stays on the page as plain text.
  • Saved by a user without the WordPress unfiltered_html capability: always filtered, even if the unfiltered setting is on. Such a user can never store a script.
  • Unfiltered mode (Settings, off by default). Ad code saved by a user who holds unfiltered_html (administrators on a single site, super administrators on multisite) is stored and output as written, including scripts. Only such a user can switch the setting on. Use it only if you trust everyone who holds that capability.

Deleting

Deleting shows a confirmation screen listing the items first. An ad that is still used by a group or placement cannot be deleted until it is removed there.

Groups

A group rotates several ads in one spot. Open RevGuard Pro → Groups, add a group, tick the ads it should include and choose a rotation:

  • Weighted random — picks an ad by its weight on every page. A higher weight is shown more often.
  • In order — uses the order numbers you set and shows the first ad that is currently allowed to appear.

Only active ads that are within their schedule are eligible. A group that is used by a placement cannot be deleted until the placement is changed.

Placements

A placement tells the plugin where to insert an ad or group automatically. Open RevGuard Pro → Placements, add one and choose What to show (a single ad or a group) and a Position:

PositionSetting that goes with it
Before the content—
After the content—
After a paragraphParagraph number, 1 to 100
After a headingHeading level, H2 to H6, and which heading of that level (1 = the first)
At a point in the contentPercent of the content
Manual (shortcode or block only)The placement is kept but nothing is inserted automatically

Priority sets the order in which placements are applied: lower numbers first, and placements with equal numbers in the order they were created (lowest id first). Only one ad is placed at each spot, so if two placements want the same spot the lower number wins and the other is skipped. It never changes which ad a group picks. At most 20 ads are inserted automatically into one page. An active placement needs an ad or group to show. Automatic placements apply to the main content on your site's front end; they are not applied in feeds, REST responses, admin screens, embeds or excerpts. You can turn automatic insertion off completely in Settings.

Shortcode and block

To place an ad by hand, use the shortcode with the id shown in the Ads or Groups list:

[revguard_pro ad="12"]
[revguard_pro group="3"]
[revguard_pro ad="12" class="my-class other-class"]

Give exactly one of ad or group. class is optional (up to three simple class names). Invalid shortcodes show nothing rather than an error.

In the block editor, add the RevGuard Pro Ad block and choose an ad or group. The same ad is not repeated twice in the same post.

For safety, a shortcode or block inside a post only shows ads when the post's author is allowed to manage ads. Outside posts (for example in a widget) it is always allowed.

Analytics

RevGuard Pro → Analytics shows impressions per day and your top ads for the last 7, 30 or 90 days.

What is counted. One number only: how many times an ad's markup was added to a page your server built, per ad per day. It is not viewability, not clicks, and not an ad-network figure. No visitor information is stored and no clicks are tracked. Pages served from a full-page cache do not run the plugin, so those views are not counted — these figures are not traffic totals.

You can switch counting off and choose how long daily totals are kept in Settings.

Targeting

The plugin's engine can evaluate targeting rules — device, post type, taxonomy, logged-in state, user role, URL, referrer and query parameter — and an ad that has such rules only shows when they match. Version 1.0 has no screen for creating or editing targeting rules. Ads and placements are shown to everyone unless they already carry rules. Existing rules are never lost: they are preserved every time you save, and the edit form shows a read-only summary (Everyone, Restricted by rules, or Unreadable (matches nothing)).

Scheduling

Each ad can have a start and an end time. Times are entered and shown in your site's time zone (set in Settings → General). Before the start time or after the end time the ad is not shown; with both empty it is always eligible. In groups, only ads inside their schedule take part in the rotation.

Cache compatibility

Page caching plugins and hosts store a finished page and serve it again, so the plugin cannot run for those visitors. To avoid freezing the wrong ad into a cached page, RevGuard Pro does the following:

  • When a page involves an ad whose outcome depends on request details (device, referrer or query parameters), the plugin asks page caches not to store that response, by defining the DONOTCACHEPAGE constant and sending no-cache headers when headers have not been sent yet.
  • Outcomes that are stable for a page, or that depend on whether a visitor is logged in or on their role, stay on the normal cache path. Whether your cache serves logged-in visitors separately depends on your caching setup, so check it if you target by login state or role.
  • Developers can listen to the revguard_pro_cache_decision action, which receives the decision and the time of the next schedule change.
This is best-effort. It depends on your caching plugin honouring DONOTCACHEPAGE at the end of the request. A cache that decided earlier, headers that were already sent, a server or CDN cache that serves pages without running WordPress, or a page already stored in a cache cannot be controlled by the plugin. The plugin does not purge caches. When you change ads, groups, placements or schedules — or when a schedule starts or ends — clear your page cache so visitors see the new state.

Privacy and external requests

  • RevGuard Pro's own code makes no external requests, sets no cookies and stores no visitor personal data. Analytics count ad renderings per day and nothing about the visitor.
  • Your ad code is separate. In the default filtered mode, scripts and frames are removed, so ad code can only show text, links and images; an image or link may of course point to another site. In unfiltered mode, ad code is output as written, so any script, tag or pixel in it runs in your visitors' browsers and may contact third parties, set cookies or process visitor data under their own terms. RevGuard Pro does not control or inspect that.
  • Consent: RevGuard Pro does not include a consent tool. You are responsible for any notice or consent your site needs for the ad code you use.

Who can use it

Access uses three capabilities, granted to the Administrator role when the plugin is activated. There is no network-admin menu on multisite; each site has its own ads and settings.

CapabilityAllows
rgp_manage_adsDashboard, Ads, Groups, Placements
rgp_view_analyticsAnalytics
rgp_manage_settingsSettings

Each user sees only the screens their capabilities allow. Every change needs both the capability and a valid security token.

Uninstalling and your data

  • Deactivating keeps all your data.
  • Deleting the plugin keeps your data too, unless you turned on Delete all data when the plugin is deleted in Settings before deleting. With that on, your ads, groups, placements, statistics and settings are removed (on multisite, for each site that turned it on).

Translation

The plugin is translation-ready (text domain revguard-pro). A template file, languages/revguard-pro.pot, is included. Put translation files named revguard-pro-<locale>.mo (and .po) in the plugin's languages folder, or use a translation tool such as Loco Translate.
